
# DOKUMEN PERENCANAAN PROYEK SIPPA

## 1. Identitas Proyek

Nama proyek: Sistem Informasi Peminjaman dan Pengembalian Alat (SIPPA)

Jenis aplikasi: Aplikasi berbasis web

Metode pengembangan: SDLC Waterfall

Teknologi awal: PHP, HTML, CSS, Git, dan GitHub

## 2. Latar Belakang

Pencatatan peminjaman dan pengembalian alat secara manual
dapat menyulitkan pengelola dalam memantau ketersediaan alat,
mencatat identitas peminjam, serta mengetahui riwayat transaksi.

SIPPA direncanakan untuk membantu proses pendataan alat,
peminjaman, pengembalian, dan pemantauan ketersediaan alat
secara terstruktur.

## 3. Tujuan Proyek

1. Mempermudah pengelolaan data alat.
2. Mempermudah pencatatan peminjaman dan pengembalian.
3. Membantu pemantauan stok alat yang tersedia.
4. Menyediakan riwayat transaksi peminjaman.

## 4. Ruang Lingkup

Termasuk dalam ruang lingkup:
- Pengelolaan data alat.
- Pencatatan data peminjam.
- Pencatatan transaksi peminjaman.
- Pencatatan pengembalian alat.
- Pemantauan status ketersediaan alat.
- Riwayat peminjaman dan pengembalian.

Di luar ruang lingkup tahap awal:
- Integrasi pembayaran.
- Integrasi perangkat IoT.
- Aplikasi mobile native.

## 5. Tahapan SDLC Waterfall

### 5.1 Analisis Kebutuhan
Mengidentifikasi pengguna, masalah, kebutuhan fungsional,
dan kebutuhan nonfungsional sistem.

### 5.2 Perancangan Sistem
Menyusun alur proses, diagram konteks, ERD, rancangan
basis data, dan rancangan antarmuka.

### 5.3 Implementasi
Mengembangkan aplikasi berdasarkan rancangan yang telah
disetujui menggunakan teknologi yang dipilih.

### 5.4 Pengujian
Menguji fungsi pengelolaan alat, peminjaman, pengembalian,
validasi input, dan hak akses pengguna.

### 5.5 Pemeliharaan
Memperbaiki kesalahan dan menyesuaikan sistem berdasarkan
hasil evaluasi serta kebutuhan pengguna.

## 6. Risiko Proyek

1. Kebutuhan pengguna belum teridentifikasi secara lengkap.
2. Terjadi kesalahan pencatatan data.
3. Pengembangan memerlukan waktu lebih lama dari rencana.
4. Terjadi konflik perubahan kode pada Git.

Mitigasi:
- Melakukan klarifikasi kebutuhan pengguna.
- Memvalidasi data sebelum disimpan.
- Membagi pekerjaan menjadi beberapa tahap.
- Menggunakan branch dan pull request untuk perubahan kode.

## 7. Hasil yang Diharapkan

Dokumen analisis dan rancangan SIPPA, repositori kode
yang terdokumentasi, serta prototipe awal untuk
mendukung pengembangan sistem selanjutnya.
